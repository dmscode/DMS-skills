# 笔记仓库文件组织

> [!abstract] 适用范围
> 本技能规定笔记仓库的**文件组织**（放哪、怎么归置）；单篇笔记的格式（Front Matter、Markdown 语法、内容规范）由 `obsidian-note-format` 技能规定。两者配合使用。
> 操作仓库时若当前环境有 Obsidian CLI 可用，优先用 CLI 执行创建、编辑、整理、移动；CLI 不可用时才自行或脚本操作。

## 一、顶层结构

```text
00_收集/          临时文件：待整理的笔记、测试沙盘文件等
├── 01_摘抄/      摘抄材料（先保存，待消化转换为己述）
├── 02_灵感/      灵感、闪念
├── 03_绘图/      绘图草稿（canvas / excalidraw）
└── 09_沙盘/      测试沙盘文件
10_索引/          全局文件地图（MOC）、索引视图（以 .base 为主）
20_工作/          工作维度笔记（含 工作/理论、工作/实践 两个象限）
30_生活/          生活维度笔记（含 生活/理论、生活/实践 两个象限）
├── 31_日记/      每日笔记
├── 32_周记/      每周回顾与总结
├── 33_清单/      各类清单（待办、检查项、常备列表）
├── 34_方法/      生活方法与操作细则（菜谱、家中设备操作细则等）
└── 35_记录/      按事件/项目记录：某事件的完整整理、某一类信息的整体记录
40_资料/          资料库（文档与视觉制品，按功能定义，不按格式）
├── 41_文档/      供查阅的文档：说明书、产品/软件文档、规格书、标准、保单合同等
└── 42_视觉/      视觉制品：图、表、思维导图、canvas / excalidraw、图标等
90_资源/          资源类内容（支撑工具）
├── 91_plugins/   Obsidian 插件相关资源（按插件划分，一个插件一个文件夹）
│   └── <插件名>/  该插件自己的资源（第三层，不编号）
├── 92_templates/ 各种笔记模板
├── 93_scripts/   脚本库：可复用脚本（按功能/方向分夹，每脚本配说明文档）
└── 99_AI/        AI 工作区（每子夹 = 一个 workspace，按功能中文命名，模板见下）
```

`40_资料` 的内容按功能定义、不按格式。首批两个子夹（更多小分类后续按同一规则增添——子夹编号 `43_`、`44_`……，id 第二字母取小分类英文词首字母）：

- `41_文档`：供查阅的文档——设备说明书、产品/软件文档、规格书、标准规范、API 文档、保单/合同等（id 字母 `D` = Documents，首标签 `资料/文档`）；
- `42_视觉`：视觉制品——图、表、思维导图、`.canvas` / `.excalidraw.md`、图标等产出资产（id 字母 `V` = Visuals，首标签 `资料/视觉`）。

> **组织哲学**：文件夹结构只承担**物理归置**（东西放在哪）；**最终的笔记组织依靠 `10_索引` 中的地图与 MOC**（怎么找到、怎么串联）——不用文件结构表达全部组织关系。

## 二、命名与编号规则

- **编号的含义**：编号是对文件夹**地位的确立**——带编号表示该文件夹**长期存在、不打算变动**；因此编号只给确定会长驻的结构，临时性、系列性的子文件夹**可以不编号**。
- **编号只标记两层**：第一层（顶层）与第二层（子夹）带编号，**第三层及以下不编号**（如 `91_plugins/dataview/`）。
- 顶层：**两位数字前缀 + 下划线 + 中文名**，如 `20_工作`；号码**留足间隔**（当前为 00/10/20/30/40/90），便于插入新顶层文件夹。
- 第二层编号 = **上层编号的第一位 + 顺序数字**——如 `90_资源` 的子夹为 `91_`、`92_`……`99_`，`00_收集` 的子夹为 `01_`、`02_`……；号码可留间隔（如 AI 用 `99_`），便于插入。
- 第三层及以下按名称分设，不再编号（如 `91_plugins` 内按插件名分夹，一个插件一个文件夹）。
- **编号指代**：日常沟通中可直接用编号指代文件夹——按上述规则解析：两位整数（如 `20`）= 顶层夹；`上层第一位 + 序数`（如 `31`）= 该上层夹的第 N 个子夹（`31` → `30_生活/31_日记`）。

## 三、各文件夹的归属规则

- **00_收集**：临时文件——待整理的笔记、测试沙盘文件。子夹划分：
  - `01_摘抄`：摘抄材料——先保存，待消化转换为自己的表述后才成为正式笔记；
  - `02_灵感`：灵感、闪念；
  - `03_绘图`：绘图草稿（canvas / excalidraw 临时文件）；
  - `09_沙盘`：测试沙盘文件。
- **10_索引**：全局文件地图（MOC）、索引视图——**以 `.base` 文件为主**（纯 YAML，无 Front Matter、无 id 与标签，靠标签/文件夹条件查询其他笔记）；Markdown 索引用**索引维度**（首标签 `索引`，id `M<侧重字母>-日期-识别符`，规则见 `obsidian-note-format` 技能）。**夹内常住文件**：`标签表.md`（标签登记册，MG 维度）与 `标签统计.base`（各标签笔记数，Obsidian 引擎自动算）——标签的受控增长机制见 `obsidian-note-format` 技能。
- **20_工作 / 30_生活**：按第一轴（工作/生活）归置**自己的笔记**；象限裁切规则（非生活类归工作等）见 `obsidian-note-format` 技能。**两者是大分类，其下小分类各自独立，不在大分类之间产生冲突**（如 `34_方法` 只收生活侧方法；工作侧方法归 `20_工作` 内部，不并夹）。`30_生活` 已建五个子夹：`31_日记`（每日笔记）、`32_周记`（每周回顾与总结）、`33_清单`（各类清单：待办、检查项、常备列表）、`34_方法`（生活方法与操作细则，如菜谱、家中设备操作细则）、`35_记录`（按**事件/项目**记录——某事件的完整整理、某类信息的整体记录；与 31/32 的**按时间**记录相区别）；`20_工作` 内部结构**应用后自然生长**，不预先设计。系列化子夹的编号按上述标准（长期系列可编号，临时系列不编号）；此层的组织主要服务于物理归置，串联与导航靠 `10_索引`。
- **40_资料**：**资料库**——按功能定义、不按格式。子夹：`41_文档`（供查阅的文档）、`42_视觉`（视觉制品与产出资产）；其中的 md 文件使用**资料维度**（首标签 `资料/<小分类>`、id `R<小分类字母>-日期-识别符`，规则见 `obsidian-note-format` 技能），其余规则基本同主规范。
- **90_资源**：**只放支撑工具类文件**。子夹划分：
  - `91_plugins`：插件相关资源，**按插件划分、一个插件一个文件夹**（如 `91_plugins/dataview/`），插件夹内不再编号；
  - `92_templates`：各种笔记模板；
  - `93_scripts`：**脚本库**——各类**可复用**脚本；内部按功能/方向设子文件夹；**每个脚本必须配有对应的说明文档**（用途、用法、参数、注意）；脚本说明文档属工具文档，不强制遵循格式规范；
  - `99_AI`：**AI 工作区**——每个子夹 = 一个 workspace，按功能中文命名（workspace 为按需创建，不预设计、不编号）；本技能只规定其在仓库中的定位，**初始化流程、目录模板、AGENTS.md 模板与映射记录见 `obsidian-workspace-init` 技能**。

### AI 工作区（workspace）——定位声明

workspace 的完整初始化（目录模板、AGENTS.md 模板、映射记录、安全约定）由 `obsidian-workspace-init` 技能规定，本技能不重复。此处只声明定位：

- workspace 可以是**映射叠加出的虚拟目录**（如 Docker overlay），`notes/` 与 `skills/` 的内容可映射自其他位置；
-  workspace 内的 `AGENTS.md` 是工作区最高说明；其私有设定优先于通用技能；
- 建新工作区或改工作区结构时，加载 `obsidian-workspace-init` 技能。

### 参考资料的二分法则

- **自写的参考笔记**（读后自己写的摘要、教程笔记）：是自己的内容 → 按维度归 `20_工作`/`30_生活`；
- **供查阅的资料原件**（说明书、参考图示）：是查阅材料 → 归 `40_资料`。

### 图形文件（`.canvas` / `.excalidraw.md`）的位址规则

- **不进入 `20_工作`/`30_生活` 笔记体系**，家在 `40_资料`；
- **例外许可**：可以出现在 `10_索引`（如用作可视化地图）和 `00_收集`（临时/待整理）；
- 格式特性：`.canvas` 为 JSON，无 Front Matter，故无 id 与标签；`.excalidraw.md` 的 Front Matter 特例（保留 `excalidraw-` 属性、必须含 `excalidraw` 标签）见 `obsidian-note-format` 技能。

#### Excalidraw 衍生物的整体性

- 同目录下与 `.excalidraw.md` **同名**（不同后缀）的 **png / svg** 图片，视为该 Excalidraw 文件的**衍生物**（导出品）；
- **移动、改名等操作中，衍生物与源文件视为一个整体，一同处理**——如 `架构图.excalidraw.md` 改名为 `系统架构图.excalidraw.md`，则 `架构图.png`、`架构图.svg` 必须同步改名，三者始终同目录；
- 该规则是附件同名文件夹规则的例外：衍生物**不进**同名子文件夹，与源文件同目录同名放置（附件规则见 `obsidian-note-format` 技能）。

## 四、与格式规范的关系（两个技能的接口）

- **分工**：本技能管"文件放哪"（文件夹归属与编号）；`obsidian-note-format` 技能管"笔记写成什么样"（Front Matter、Markdown 语法、内容规范）。两者配合使用，不重复声明。
- **附件规则**：附件仍存于笔记同目录的同名文件夹内（规则见 `obsidian-note-format` 技能），不因本技能的顶层结构而改变；Excalidraw 衍生物为例外（见上）。
- **适用边界**：格式规范仅在 AI 创建/编辑笔记或用户要求整理时生效——用户让 AI 往 `00_收集` 创建则按格式书写，用户自己手写的文件不强制合规；`40_资料` 内 md 文件已定——资料维度 + 基本遵循主规范。
- **操作方式**：操作仓库时若当前环境有 Obsidian CLI 可用，优先用 CLI 执行创建/编辑/整理/移动等操作；CLI 不可用时才自行或脚本操作——本技能的归属规则（文件放哪）不随操作方式改变。
