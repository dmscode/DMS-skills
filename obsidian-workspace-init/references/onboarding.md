# 用户引导：参数清单驱动的工作区创建

> 本文件是 `obsidian-workspace-init` 技能的引导流程参考。**当用户要求新建工作区但需求模糊、或明确要求引导时加载本文件**；需求完整时走 SKILL.md 标准六步流程，不必引导。

## 一、核心机制：参数清单

引导的本质是**参数完整性保障**——创建工作区的参数多，用户会遗忘，所以 AI 持有一份固定清单逐项确认，不依赖用户记得要定什么。

每个参数只有三种归宿，引导全程公开追踪：

| 标记 | 含义 |
|---|---|
| ✅ 已确认 | 用户明确回答了 |
| 🔵 默认 | 用户说“行/默认”，采用默认值 |
| ⏭️ 跳过 | 可选参数用户暂不决定（须告知补充路径） |

**状态表规则**：每轮用户回答后，在回复末尾附一行紧凑状态表；引导跨轮次时，每轮开头先重述状态表——用户随时知道“定了什么、还剩什么”。

## 二、参数清单（7 组）

| # | 参数 | 必填？ | 默认值 |
|---|---|---|---|
| A1 | 功能名（中文，成为目录名 `99_AI/<名字>/`） | ✅ | 无 |
| A2 | 一句话描述（写入 AGENTS.md 的 description） | ✅ | 无 |
| A3 | 边界：不做什么 | 建议 | 空 |
| B1 | notes 来源：空 / 原生放入 / 映射 | ✅ | 空（以后加） |
| B2 | notes 映射详情：源路径、读写、性质 | 映射时 ✅ | — |
| C1 | skills 来源：空夹用全局 / 放项目技能 / 映射技能包 | ✅ | 空夹 + 全局技能 |
| C2 | skills 映射详情：源路径 | 映射时 ✅ | — |
| D1 | work/ 子夹 | 可选 | `scripts/` + `logs/` |
| E1 | 工作约定（放哪、禁碰、产出归哪） | 建议 | 只带安全约定 |
| F1 | AGENTS.md 的 id 与首标签 | 自动 | `AA-八位日期-尾符` / `AI/Agent_md` |
| G1 | 安全约定三条 | 自动 | 全带，告知即可 |

## 三、四步流程

### 第 1 步：出示清单

创建前先把 7 组参数整体列给用户：“建一个工作区需要定这些，一项一项来，多数有默认值，你说‘行’就用默认。”——**先给全貌，再逐项确认**，这是防遗忘的第一道闸。

### 第 2 步：逐组确认

一次只问一组；每组给问句、默认值、一句人话解释。参考问句：

- **A1 功能名**：“这个工作区叫什么？中文，两三到五个字，比如‘博客工厂’‘笔记整理’。它会成为目录名 `99_AI/<名字>/`。”
- **A2 一句话描述**：“用一句话说它做什么——写进 AGENTS.md，以后你或别的 AI 一眼就知道这工作区干什么。”
- **A3 边界**：“它**不**做什么？比如‘不碰正式夹’‘不做发布’。边界比目标更能防止工作区膨胀。”（可跳过）
- **B1 notes 来源**：“notes 里放哪些笔记？a) 先空着以后加；b) 从正式夹（20_工作/30_生活）拣几张进来；c) 映射整个目录——文件还在原处，AI 在这里读写，改的就是原文件，备份你做。”（默认 a）
- **B2 映射详情**（仅选 c 时问）：“映射哪个目录？映射进来的笔记默认可写。”
- **C1 skills 来源**：“需要项目技能吗？a) 不需要，用全局技能——默认建个空的 `.agents/skills/` 占位；b) 放几个项目自有技能；c) 从共享技能包映射——技能在别处维护，改一处、多个工作区同时受益。”（默认 a）
- **C2 映射详情**（仅选 c 时问）：“映射哪个技能包目录？技能默认只读。”
- **D1 work/ 子夹**：“AI 的产出放哪？默认建 `scripts/`（脚本）和 `logs/`（日志），要加别的吗（如 `output/`、`drafts/`）？”（可跳过）
- **E1 工作约定**：“还有什么要约定的？安全约定（技能只读、映射记录禁操作、备份责任）默认自动带上，不用你操心。”（可跳过）
- **F1/G1**：不提问，创建后告知“id 和标签已按规范自动生成，安全约定已默认带上”。

### 第 3 步：完整性检查

全部过完后，亮出完整状态表（✅/🔵/⏭️ 逐项），并：

- **必填项（A1/A2/B1/C1）有缺失 → 追问**，不进入创建；
- **跳过的可选项 → 说明补充路径**（如“D1 跳过了，以后想在 work/ 加目录时告诉我”）；
- 映射项（B2/C2）确认已记录映射详情。

### 第 4 步：复述创建

完整复述所有决定（功能名、描述、边界、notes 配置、skills 配置、work/ 结构、约定）→ 用户点头 → 按 SKILL.md 标准六步流程执行创建 → 创建后报告“建了什么、每处放什么、映射了什么、还有什么待定”。

## 四、交互规则

1. **一次一问**：一条消息只问一组，答完再问下一组；
2. **默认先行**：每组都带默认值，用户说“行/默认”即可通过；
3. **概念随问随解释**：问到“映射”才解释映射，不提前灌输；
4. **允许跳过**：任何可选组用户说“先空着/跳过”就跳过，不穷追猛打；
5. **先复述后动手**：创建前完整复述，确认才执行；
6. **不替用户编**：用户表达模糊时，给 2~3 个选项让用户挑，不自行发挥；
7. **可用宿主工具，但不依赖**：如果当前 agent 软件提供问答/问卷/表单类工具（结构化提问、选项按钮等），可以用它收集参数，体验更好；**不限定具体 agent 软件**——没有这类工具就用普通对话逐问，效果相同。本技能不依赖任何特定 agent 的功能。

## 五、与标准流程的交接

引导只负责“把参数定全”；参数齐后，交接 SKILL.md 的六步流程（建结构 → 写 AGENTS.md → 放初始内容 → 自查 → 报告）完成创建。引导中形成的决定直接作为各步的输入。
